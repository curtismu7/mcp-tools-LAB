Known edges, stated plainly:

- The tool connects to any URL the operator types, including loopback and private addresses. That is its job; it is not an SSRF-hardened proxy, which is why it binds loopback and checks `Host` and `Origin`.
- The confirm step is a contract of the API and the UI. A script on this machine that passes the same-origin check can call the preview endpoint and then the call endpoint. The step protects against a click you did not mean and against changed arguments, not against a hostile local process.
- The UI gates calls behind a scan; the API does not (a scan is not a permission).
- A token is stored in clear in the mode 600 file so calls can authenticate. The file is as safe as your home directory.
- If a token is shorter than four characters it is not redacted.
- **In Docker, stdio connections launch processes inside the container**, with the container's network. The container is read-only, drops all capabilities and publishes on loopback only, but it is the operator's typed command that runs.
- **The confirm gate does not cover the live proxy.** An agent connected through it calls tools on its own; the proxy only shows what it does. While the proxy is on, anything that has the proxy token can use the saved connection's credential through it. The token keeps out web pages and other sites; it is **not** a barrier against programs already running as you on this machine, which can read it from `GET /api/proxy` (as they can read the saved connections file itself). That is why the proxy is off by default, the token changes each time it is turned on, and turning it off closes every open stream.
- The proxy scrubs the saved credential (and the proxy token) out of what the client receives as well as out of the log, including a secret split across chunks or JSON-escaped. A secret in a shape the server changed (re-encoded, split by other text) is not recognised.
- **OAuth metadata fetches are not SSRF-hardened:** URLs must be https (or loopback http) and are not redirected, but a name that resolves to a private address is not refused. The proxy token and OAuth tokens are scrubbed from replies and logs, including a token refreshed during the call.
- The Sign in dialog sends the password to this tool, which passes it to PingOne; PingOne's own lockout is the only throttle beyond the 5-starts-a-minute limit. MFA, consent and SSO-only policies are not driven.
- The scan rules are heuristics; see [scan-rules.md](scan-rules.md) for what each one misses.
