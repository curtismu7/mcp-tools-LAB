# Architecture

One repo, one app: an Express server (`server/`) that serves a React + Vite page (`web/`), npm workspaces, Node ESM.

```
browser (web/dist)  --same origin-->  Express (server/src/app.js)
                                        |-- security.js   loopback bind, Host check, same-origin writes
                                        |-- store.js      connections.json (mode 600); stdio kept in memory only
                                        |-- mcp/          Streamable HTTP and stdio clients, protocol methods, manager
                                        |-- scanner/      rule table, engine, unicode, report, live scan, CLI
                                        |-- canonical.js  the arguments shown to the operator and their hash (confirm gate)
                                        |-- redact.js     a token never leaves, even if a server echoes it
                                        |-- health.js     GET /api/health (demo-health/1) from doctor.js checks
```

## One path through it

1. **Connect.** `POST /api/connections` saves the connection and sends `initialize` only. A token is stored in `connections.json` and is never returned (`set` is all the API or UI says).
2. **See.** `GET /api/connections/:id/tools` lists the tools (all pages). Resources and prompts are listed the same way. The page renders every string from the server as inert text.
3. **Judge.** `POST /api/connections/:id/scan` lists tools, resources and prompts and, unless turned off, reads resource and prompt content, then runs the rule table (`server/src/scanner/rules.js`, documented in [scan-rules.md](scan-rules.md)) over what it received. It returns a `scan-report/1`. It never sends `tools/call`. **It reports; it never blocks.**
4. **Call.** `POST .../call/preview` returns the exact arguments (canonical JSON) and `argsHash`. `POST .../call` needs `{confirm:true, argsHash}`: 428 without confirm, 409 on a changed hash, nothing sent to the server before the gate. The UI keeps calls locked until the connection has been scanned in this session; the API does not require a scan (a scan is not a permission).
5. **Offline.** `POST /api/scan` takes a pasted or loaded `tools/list` snapshot (or an array of tools, or an A2A Agent Card) and runs the same engine with no server. Size capped, 413 beyond it.

The same engine runs from the command line (`npm run scan`, exit codes in the README).

## The web app

Pages: Connect, Server (Tools, Resources, Prompts, Scan, findings, Call a tool), Scan a snapshot, Stories (two, with presenter mode), How it fits (a ReactFlow diagram: movable boxes, Simulate, Reset, speed), Limits. Light and dark themes through tokens; no purple.

## Where the code came from

Copied with a header comment in each file (never imported across repos) from AI-DEMO2 `standalone/mcp-inspector` and `standalone/mcp-scanner`; patterns (health contract, doctor, hooks, CI, e2e, content pack) from the ID-JAG kit, the SE shelf and hostile-mcp.
