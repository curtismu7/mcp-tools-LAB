# Changelog

## Unreleased

- Changed: a three-key comparison on gateway `v1.261106` (2026-11-09) showed access differs by caller at the level of a whole aggregate. The banner and docs now say so; per-tool filtering per caller is still UNVERIFIED. Re-vendored `standalone-ui.css` from the family's main.
- Added: a 401 Bearer challenge on a call made through the live proxy (per-server or one URL) also brings up the OAuth sign-in on the Server page, and a 403 that names missing scopes for a signed-in user now says which scope is missing and what has to be true for it to be requested (`mcp_scope_needed`).
- Added: a server that answers initialize and tools/list anonymously but refuses `tools/call` (the Banking MCP server) now gets the OAuth sign-in. A 401 Bearer challenge on a call is remembered, the sign-in card appears, and you run the call again after signing in.
- Changed: the Entitled listing banner and docs now say which gateway version was measured. Our SE gateway runs `v1.261106` (after the 2026-11-02 release), and Real measured the listing and the cap on it; per-caller entitlement is still UNVERIFIED (one agent key). Added the optional `MCP_TOOLS_GW_VERSION` label, shown on the Real tab. Removed the old "SE gateway is v1.261030 and does not have it" statements.
- Added: `MCPTOOLS_P1_RESOURCES=<server URL>=<audience>` lets one connection URL sign in to our PingOne for the one audience its metadata names (for example the Banking MCP server's `mcp-invest.ping.demo`); a server alone still cannot choose an audience, and the issued token's audience is checked as before. `MCPTOOLS_P1_SCOPES` and this setting can now live in `~/Development/.env`.
- Fixed: after pi.flow sign-in and every refresh the token is kept and sent only if every audience in it is the server (PingOne ignores an unknown resource and issues its own API audience); error text omits URL queries.
- Changed: **Scan a snapshot** is now three steps. It opens with the hostile sample already loaded; step 1 loads a built-in sample (hostile, clean, or an A2A Agent Card), the tools/list of one of our running servers, or your own paste or file; step 2 scans it; step 3 runs a tool against the server the snapshot came from and shows the reply (built-in samples answer with a simulated reply, our servers answer for real). Calls stay confirm-gated and unlock only after a scan of the exact text loaded; editing the text, or a pasted snapshot, turns step 3 off. The call reply scrolls into view. Server: the live store and manager accept a session-only `{transport:"mock", fixture}` connection (never written to disk). Tests: store, API, and the offline page.
- Changed: the Our servers list now covers the MCP servers that answer on this machine: banking MCP server, banking resource server, weather, Brave, audit, OpenSearch (through a port-forward), JWT verifier and MCP gateway (the last two need a token, flagged `needsToken`).
- Added: an **Our servers** dropdown on the Connect page. It lists the MCP servers this family runs locally (`server/data/known-servers.json`, loopback only), shows whether each is running, and fills every connect field when one is chosen. New `GET /api/known-servers`; a loopback TCP probe; tests for the list, the validator, the probe, the route and the page.

- Entitled listing and aggregate cap: a simulation of a Ping release claim (2026-11-02), UNVERIFIED on our tenant. `/api/gateway/*` routes, an Entitled listing page, a banner on every tab and in presenter mode, a third diagram run (with a phone layout), story MT3, content-pack terms and why-it-matters entries, a `filtered-listing` scan limit, tests with negative controls and a mutation runner (`npm run mutate`). Details: `docs/entitled-listing.md`. Fix pass: a credential typed anywhere inside a tool inputSchema is refused (bounded walk), and `gateway.credentials.test.js` plus mutants C01-C17 pin every credential rule and place. Second fix pass: edge labels on the diagram move off any box dragged onto them (the tighter layout had closed the gap they sat in) and `npm run diagram-check` drags every box in a real browser; the credential check is a named, per-rule denylist (lookbehind prefix rules, NFKC and zero-width stripping, hex, Basic-auth and password= rules, each pinned alone); `gateway.config.test.js` pins every limit and refusal with literal bounds; mutants K, R, L and B added; README test counts corrected.
